# ESP32-CAM 穿戴端

本目录是成员 B 负责的 ESP32-CAM 穿戴端工程，硬件由 **AI Thinker ESP32-CAM + OV2640 + MPU 六轴模块**组成。当前正式固件可同时运行摄像头网页、读取六轴数据，并以 50 Hz 向固定基站发送团队约定的 18 字节 UDP 数据包。

## 目录结构

```text
wearable/
├── main/
│   └── wearable_firmware/       # 当前正式固件（Arduino 草图）
├── tests/                       # 分阶段硬件自测草图
│   ├── esp32_cam_test/          # 摄像头与网页视频流
│   ├── i2c_scanner/             # 扫描 MPU 的 I2C 地址
│   ├── mpu_raw_test/            # 直接读取 MPU 寄存器
│   ├── mpu6050_test/            # Adafruit 库兼容性记录，不用于正式固件
│   ├── camera_mpu_test/         # 摄像头与 MPU 同时运行
│   └── fall_detection_test/     # 本地跌倒判定测试
└── tools/
    └── udp_receiver.py          # 电脑端 18 字节协议接收与校验工具
```

Arduino 草图要求主 `.ino` 文件与所在文件夹同名，因此正式入口为：

```text
main/wearable_firmware/wearable_firmware.ino
```

## 硬件接线

### MPU 与 ESP32-CAM

| MPU 引脚 | ESP32-CAM 引脚 | 当前线色 |
|---|---|---|
| `VCC` | `3V3` | 白 |
| `GND` | 普通 `GND` | 黑 |
| `SCL` | `GPIO15` | 紫 |
| `SDA` | `GPIO14` | 蓝 |

### ESP32-CAM-MB 与 ESP32-CAM（脱离插座调试时）

| MB 连接 | ESP32-CAM 引脚 | 当前线色 |
|---|---|---|
| 供电 | `5V` | 灰 |
| 地 | 普通 `GND` | 黑 |
| 串口发送 | `U0T` | 白 |

注意：板上标为 `GND/R` 的引脚带复位功能，不作为普通地线使用。当前方案不使用 ESP32-CAM 的 microSD 卡槽，因为 `GPIO14/15` 已用于 MPU。

## 开发环境

- Arduino IDE：已在 `2.3.10` 验证。
- 开发板：`AI Thinker ESP32-CAM`。
- 串口监视器：`115200 baud`。
- 正式固件直接读写 MPU 寄存器，不依赖 Adafruit MPU6050 库。
- 摄像头网页代码来自 Arduino ESP32 的 CameraWebServer 示例配套文件。

烧录时打开 `main/wearable_firmware/wearable_firmware.ino`，选择正确开发板和端口后上传。烧录完成后可只用稳定的 5 V 电源或充电宝供电，不要求持续连接电脑；若需要看串口日志，再连接串口线。

## 团队网络参数

| 项目 | 值 |
|---|---|
| SSID | `CSI_FALL_AP` |
| 密码 | `12345678` |
| 固定信道 | 6 |
| 基站 IP | `192.168.4.1` |
| 穿戴端静态 IP | `192.168.4.2` |
| 姿态数据目标 | `192.168.4.1:8888/UDP` |
| 抓拍命令监听 | `192.168.4.2:8889/UDP` |

正式固件已经使用上述 SSID、密码和静态地址。信道由基站 SoftAP 固定，穿戴端作为客户端接入。

## 18 字节姿态数据包

发送频率为 50 Hz，所有多字节整数均为小端序。

| 偏移 | 内容 | 类型 |
|---|---|---|
| 0–1 | 固定帧头 `AA 55` | 2 字节 |
| 2–3 | 循环包序号 | `uint16_t` |
| 4–5 | AccX 原始值 | `int16_t` |
| 6–7 | AccY 原始值 | `int16_t` |
| 8–9 | AccZ 原始值 | `int16_t` |
| 10–11 | GyroX 原始值 | `int16_t` |
| 12–13 | GyroY 原始值 | `int16_t` |
| 14–15 | GyroZ 原始值 | `int16_t` |
| 16 | Byte 2–15 的 XOR | `uint8_t` |
| 17 | 固定帧尾 `0D` | 1 字节 |

电脑端自测可运行：

```powershell
python tools/udp_receiver.py
```

出现约 `50.0 包/秒`，且晃动 MPU 时六轴原始值变化，即表示推流链路正常。

## 重要兼容性说明

1. 当前 MPU 模块在 I2C 地址 `0x68` 可正常读取，但返回 `WHO_AM_I = 0x74`。Adafruit MPU6050 库会因为型号识别不匹配而报告“没有找到 MPU6050”，所以正式固件采用寄存器直读方式。
2. 摄像头与 MPU 同时运行时，MPU 使用 `TwoWire(0)`。实测改为 `TwoWire(1)` 会出现 `I2C bus id(1) has already been acquired`。
3. 摄像头默认切到 QVGA，目的是降低延迟和内存压力；网页中继续调高分辨率可能明显卡顿。
4. `mpu6050_test` 仅保留失败排查过程，不是正式入口。
