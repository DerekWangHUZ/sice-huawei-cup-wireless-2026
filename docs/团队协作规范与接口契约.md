# 校内赛三人团队协作规范与接口契约

本规范用于明确三人之间的技术交接边界，杜绝因为“参数对不上、网络连不上、数据解不开”导致的无效扯皮。全队开发以本规范为准。

---

## 一、 A 与 B 之间的通信与硬件规范（核心）

成员 A（固定基站）与成员 B（穿戴设备）在物理上完全独立，仅通过局域网 Wi-Fi 通信。

### 1.1 Wi-Fi 网络参数约定
固定基站（ESP32-S3）自建 Wi-Fi 热点，穿戴端（ESP32-CAM）作为客户端连接：

| 参数项 | 约定值 | 说明 |
|---|---|---|
| **Wi-Fi 模式** | 2.4GHz 802.11 b/g/n | ESP32-CAM 仅支持 2.4GHz |
| **SSID（热点名）** | `CSI_FALL_AP` | 大小写敏感 |
| **密码** | `12345678` | 8 位简单密码 |
| **信道（Channel）** | **固定 6 信道** | **必须写死信道**，禁止自动切频，确保 CSI 稳定 |
| **基站 IP（A 端）** | `192.168.4.1` | ESP32-S3 SoftAP 默认网关 |
| **穿戴端 IP（B 端）** | `192.168.4.2` | 建议 B 设为静态 IP，省去 DHCP 耗时 |
| **姿态推流端口** | UDP `8888` | B 向 A 推流姿态数据 |
| **抓拍控制端口** | UDP `8889` | A 向 B 发送跌倒抓拍指令 |

---

### 1.2 姿态数据包格式规范（B $\rightarrow$ A）
* **传输频率**：**50 Hz**（每 20ms 发送一包，不得低于 30Hz，以满足跌倒冲击捕捉）。
* **数据流类型**：二进制原始字节流（小端序 Little-Endian），**总长度固定 18 字节**。

#### 字节定义详情：
| 字节偏移 | 字段名 | 数据类型 | 单位/量程 | 说明 |
|---|---|---|---|---|
| `Byte 0~1` | 帧头 | `uint16_t` | 固定 `0xAA 0x55` | 用于基站寻帧同步 |
| `Byte 2~3` | 包序号 | `uint16_t` | `0 ~ 65535` 循环递增 | A 用于统计网络丢包率 |
| `Byte 4~5` | 加速度 X | `int16_t` | MPU6050 原始读数 ($\pm 16g$) | 小端序，直接传 ADC 原始值 |
| `Byte 6~7` | 加速度 Y | `int16_t` | MPU6050 原始读数 ($\pm 16g$) | 小端序 |
| `Byte 8~9` | 加速度 Z | `int16_t` | MPU6050 原始读数 ($\pm 16g$) | 小端序 |
| `Byte 10~11`| 角速度 X | `int16_t` | MPU6050 原始读数 ($\pm 2000^\circ/s$) | 小端序 |
| `Byte 12~13`| 角速度 Y | `int16_t` | MPU6050 原始读数 ($\pm 2000^\circ/s$) | 小端序 |
| `Byte 14~15`| 角速度 Z | `int16_t` | MPU6050 原始读数 ($\pm 2000^\circ/s$) | 小端序 |
| `Byte 16` | 校验和 | `uint8_t` | 异或校验（XOR） | `Byte 2` 到 `Byte 15` 的异或值 |
| `Byte 17` | 帧尾 | `uint8_t` | 固定 `0x0D` | 结束标志 |

> **特别约定**：B 端严禁把数据转成 float 甚至字符串（如 JSON/printf）传输，极度浪费单片机算力和空口带宽，必须传上述 18 字节二进制流。

---

### 1.3 跌倒抓拍触发规范（A $\rightarrow$ B）
当固定基站判定发生跌倒时，通过网络通知穿戴端抓拍：
1. **触发报文**：A 向 `192.168.4.2:8889` 发送 4 字节 UDP 命令：`0x55 0xAA 0x01 0xFF`。
2. **B 端动作响应**：
   * 立即触发 ESP32-CAM 快门拍照一张；
   * 点亮 ESP32-CAM 板载闪光灯（GPIO 4）高亮闪烁 1 秒（**极佳的答辩视频视觉效果**）；
   * 照片在本地 Web 网页（`http://192.168.4.2/pic`）提供预览，或暂存在内存中供电脑提取。

---

### 1.4 硬件操作与指示灯约定（便于现场排障）
* **开机顺序**：**必须先开 A（基站热点），再开 B（穿戴端）**。
* **B 端板载 LED 状态定义**：
  * **快闪（每秒 3 次）**：正在搜寻/连接基站 Wi-Fi；
  * **常亮或慢闪（每秒 1 次）**：网络连接成功，正在以 50Hz 持续推流；
  * **熄灭**：供电不足或死机。
* **供电底线**：B 必须配备独立电池/小充电宝，独立输出能力不低于 5V/2A。

## 二、 A 与 C 之间的规范（数据交接与算法落地）

### 2.1 SD 卡原始数据文件导出规范（A $\rightarrow$ C）
A 存入 Micro SD 卡的文件必须采用标准 CSV 格式，方便 C 拷贝到电脑直接用 Python 或 Excel 分析：
* **文件名格式**：`/DATA_001.CSV`、`/DATA_002.CSV`（每次上电新建一个，递增编号）。
* **首行表头**：
  `Timestamp_ms,Seq,AccX,AccY,AccZ,GyroX,GyroY,GyroZ,CSI_Variance,State`
* **字段说明**：
  * `Timestamp_ms`：单片机毫秒时间戳；
  * `Seq`：穿戴端包序号（若有丢包可直接看出来）；
  * `AccX~GyroZ`：解算出来的六轴数值；
  * `CSI_Variance`：基站当前 64 个子载波的平均能量方差（或原始特征值）；
  * `State`：当前基站判定的状态（0=静止, 1=走动, 2=跌倒）。

### 2.2 跌倒判定规则交付规范（C $\rightarrow$ A）
C 不交付复杂的深度学习或大模型，仅交付**直观的参数阈值与三段式逻辑**：
1. **冲击阈值**：六轴合加速度阈值 $T_{impact}$（例如：$\sqrt{a_x^2 + a_y^2 + a_z^2} > 3.0g$）；
2. **静止窗口**：冲击发生后 1.5 秒内，姿态角变化量 $< \Delta\theta_{still}$ 且 CSI 扰动方差 $< \sigma_{csi}$；
3. **交付形式**：C 将调好的参数值填入简单的头文件定义：
   * `#define IMPACT_THRESH  xxxx`
   * `#define STILL_TIME_MS  1500`
   * `#define CSI_FALL_VAR   xxxx`
   A 直接把参数写进主控工程的 `config.h` 中即可生效。

## 三、 B 与 C 之间的规范（测试挑刺与硬件反馈）

C 充当穿戴端的“产品质检员”，两人采用**“现象反馈卡”**进行异步沟通：

* **反馈规范（C 提问题）**：C 戴上设备测试后，若发现问题，按此格式在群里发一条消息：
  > 【测试反馈】
  > * **动作**：连续快走 1 分钟 / 坐在椅子上 / 扑在垫子上；
  > * **异常现象**：电脑收到数据断帧 2 秒 / 走了 10 步没反应 / 穿戴小盒发烫；
  > * **现场状态**：板载 LED 是否在闪烁、电池电量是否充足。
* **硬件移交规范（B 交实物）**：
  * B 每次完成固件烧录或结构加固后，将设备装入小盒子，开关处贴胶带标明“ON/OFF”，直接放在实验室/宿舍固定工位；
  * C 随时取走测试，测完放回，全程无需约时间面对面交接。

## 四、 报告与视频素材提交规范（A、B $\rightarrow$ C）

为了避免最后一天通宵补材料，A 和 B 在各自模块调通后，需向 C 提交以下“图文积木”：

### 4.1 成员 A 提交清单：
1. **基站电气接线表**（简单的引脚对应表，如：S3 GPIO 10 接 SD MOSI）；
2. **基站实物清晰照**（2 张：俯视整体走线照 1 张、侧面 45 度工作通电点亮照 1 张，背景尽量干净）；
3. **板间协同说明**（50 字简述：S3 是如何通过串口发信号给 FPGA 和 STM32 的）。

### 4.2 成员 B 提交清单：
1. **穿戴端引脚说明**（注明 MPU6050 连了哪两个 GPIO）；
2. **佩戴实物照片**（2 张：设备装盒特写 1 张、志愿者绑在手臂/胸口的照片 1 张）；
3. **独立续航实测数据**（如：小充电宝供电实测连续运行 2.5 小时）。

### 4.3 成员 C 责任：
收到上述素材后，C 负责统一排版进《作品设计报告》，并统领拍摄 4 个核心镜头（静止、走动、穿墙、跌倒抓拍），在截止前 2 天完成初剪。
