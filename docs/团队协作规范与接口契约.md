# 校内赛三人团队协作规范与接口契约

本规范用于明确三人之间的技术交接边界，杜绝因为“参数对不上、网络连不上、数据解不开”导致的无效扯皮。全队开发以本规范为准。

---

## 一、 A 与 B 之间的通信与硬件规范（核心）

成员 A（固定基站）与成员 B（穿戴设备）在物理上完全独立，仅通过局域网 Wi-Fi 通信。

### 1.1 Wi-Fi 网络参数约定
固定基站（ESP32-S3）自建 Wi-Fi 热点，穿戴端（ESP32-CAM）作为客户端连接：

| 参数项 | 约定值 | 说明 |
|---|---|---|
| **Wi-Fi 模式** | 2.4GHz 802.11 b/g/n | ESP32-CAM 仅支持 2.4GHz |
| **SSID（热点名）** | `CSI_FALL_AP` | 大小写敏感 |
| **密码** | `12345678` | 8 位简单密码 |
| **信道（Channel）** | **固定 6 信道** | **必须写死信道**，禁止自动切频，确保 CSI 稳定 |
| **基站 IP（A 端）** | `192.168.4.1` | ESP32-S3 SoftAP 默认网关 |
| **穿戴端 IP（B 端）** | `192.168.4.2` | 建议 B 设为静态 IP，省去 DHCP 耗时 |
| **姿态推流端口** | UDP `8888` | B 向 A 推流姿态数据 |
| **抓拍控制端口** | UDP `8889` | A 向 B 发送跌倒抓拍指令 |

---

### 1.2 姿态数据包格式规范（B $\rightarrow$ A）
* **传输频率**：**50 Hz**（每 20ms 发送一包，不得低于 30Hz，以满足跌倒冲击捕捉）。
* **数据流类型**：二进制原始字节流（小端序 Little-Endian），**总长度固定 18 字节**。

#### 字节定义详情：
| 字节偏移 | 字段名 | 数据类型 | 单位/量程 | 说明 |
|---|---|---|---|---|
| `Byte 0~1` | 帧头 | `uint16_t` | 固定 `0xAA 0x55` | 用于基站寻帧同步 |
| `Byte 2~3` | 包序号 | `uint16_t` | `0 ~ 65535` 循环递增 | A 用于统计网络丢包率 |
| `Byte 4~5` | 加速度 X | `int16_t` | MPU6050 原始读数 ($\pm 16g$) | 小端序，直接传 ADC 原始值 |
| `Byte 6~7` | 加速度 Y | `int16_t` | MPU6050 原始读数 ($\pm 16g$) | 小端序 |
| `Byte 8~9` | 加速度 Z | `int16_t` | MPU6050 原始读数 ($\pm 16g$) | 小端序 |
| `Byte 10~11`| 角速度 X | `int16_t` | MPU6050 原始读数 ($\pm 2000^\circ/s$) | 小端序 |
| `Byte 12~13`| 角速度 Y | `int16_t` | MPU6050 原始读数 ($\pm 2000^\circ/s$) | 小端序 |
| `Byte 14~15`| 角速度 Z | `int16_t` | MPU6050 原始读数 ($\pm 2000^\circ/s$) | 小端序 |
| `Byte 16` | 校验和 | `uint8_t` | 异或校验（XOR） | `Byte 2` 到 `Byte 15` 的异或值 |
| `Byte 17` | 帧尾 | `uint8_t` | 固定 `0x0D` | 结束标志 |

> **特别约定**：B 端严禁把数据转成 float 甚至字符串（如 JSON/printf）传输，极度浪费单片机算力和空口带宽，必须传上述 18 字节二进制流。

---

### 1.3 跌倒抓拍触发规范（A $\rightarrow$ B）
当固定基站判定发生跌倒时，通过网络通知穿戴端抓拍：
1. **触发报文**：A 向 `192.168.4.2:8889` 发送 4 字节 UDP 命令：`0x55 0xAA 0x01 0xFF`。
2. **B 端动作响应**：
   * 立即触发 ESP32-CAM 快门拍照一张；
   * 点亮 ESP32-CAM 板载闪光灯（GPIO 4）高亮闪烁 1 秒（**极佳的答辩视频视觉效果**）；
   * 照片在本地 Web 网页（`http://192.168.4.2/pic`）提供预览，或暂存在内存中供电脑提取。

---

### 1.4 硬件操作与指示灯约定（便于现场排障）
* **开机顺序**：**必须先开 A（基站热点），再开 B（穿戴端）**。
* **B 端板载 LED 状态定义**：
  * **快闪（每秒 3 次）**：正在搜寻/连接基站 Wi-Fi；
  * **常亮或慢闪（每秒 1 次）**：网络连接成功，正在以 50Hz 持续推流；
  * **熄灭**：供电不足或死机。
* **供电底线**：B 必须配备独立电池/小充电宝，独立输出能力不低于 5V/2A。

## 二、 A 与 C 之间的规范（数据交接与算法落地）

### 2.1 SD 卡原始数据文件导出规范（A $\rightarrow$ C）
A 存入 Micro SD 卡的文件必须采用标准 CSV 格式，方便 C 拷贝到电脑直接用 Python 或 Excel 分析：
* **文件名格式**：`/DATA_001.CSV`、`/DATA_002.CSV`（每次上电新建一个，递增编号）。
  * 编号由固件**上电时扫描卡上已有 `DATA_nnn.CSV` 取最大号 +1** 得到，因此跨断电持续递增，无需依赖 NVS。
  * 卡未挂载（未插卡/挂载失败）时不建文件，基站其余功能照常运行。
* **首行表头**：
  `Timestamp_ms,Seq,AccX,AccY,AccZ,GyroX,GyroY,GyroZ,CSI_Variance,State`
* **行尾**：`\n`（LF），无 `\r`，无引号包裹。
* **频率**：每解出一个合法姿态帧写一行（穿戴端 50Hz 推流，即约 50 行/秒）。
* **字段说明**：
  * `Timestamp_ms`：基站上电起的毫秒时间戳（`esp_timer` 单调时钟）；
  * `Seq`：穿戴端包序号（若有丢包可直接看出来）；
  * `AccX~GyroZ`：**原始 int16 ADC 值**（与 §1.2 空口传的原始值一致，不做浮点换算）。
    换算关系：加速度 2048 LSB = 1g，角速度 16.384 LSB = 1°/s（见 `fall_core.h`）；
  * `CSI_Variance`：基站当前一帧 CSI 的子载波幅度方差（10 帧滑窗平均）。
    **默认构建（`BS_CSI_IMPL=stub`）为占位值 0**；采集与统计通路位于
    `csi_stats.c` / `csi_real.c`，以 `-DBS_CSI_IMPL=real` 构建后本列为
    有效值（子载波数由 `csi_info->len` 动态决定）；
  * `State`：当前基站判定的状态，取值与 §4.3 状态码**完全一致**（4 值）：
    `0=IDLE`（静止）、`1=WALK`（走动）、`2=FALL_PENDING`（冲击后确认窗口内）、`3=FALL_CONFIRMED`（跌倒确认）。

> **`State` 取值为 4 值**（与 §4.3 完全一致），C 侧解析脚本按 4 值处理，
> 不得把 `FALL_PENDING` 误读成"已跌倒"。
>
> **实现与验证**：表头与行格式集中定义在
> `firmware/base_station/main/log_fmt.c`，并由
> `firmware/base_station/tools/offline_test/` 的宿主机离线自测逐字节断言
> （场景 9~11），保证文档、固件两侧格式一致。


### 2.2 跌倒判定规则交付规范（C $\rightarrow$ A）
C 不交付复杂的深度学习或大模型，仅交付**直观的参数阈值与三段式逻辑**：
1. **冲击阈值**：六轴合加速度阈值 $T_{impact}$（当前 3.0g，宏名 `IMPACT_THRESH_G`，见 `firmware/base_station/main/fall_core.h`）；
2. **静止窗口**：冲击发生后【持续】静止满 1.5 秒即确认跌倒（静止判据：角速度
   $< 50°/s$ 且合加速度回到 $1g \pm 0.35g$；静止被运动打断则计时清零重来；
   冲击后 4 秒观察上限内未确认则按非跌倒退出）。另有 CSI 扰动方差辅助判据
   （`CSI_JUDGE_ENABLE=0` 默认关闭，开启后确认时额外要求窗口方差
   < `CSI_FALL_VAR_MAX`，即 sigma_csi；CSI 未就绪时 fail-open 放行），
   sigma_csi 标定后启用；启用前置（CSI Kconfig/promiscuous/首帧延迟初始化）与 v6.1 SoftAP 限制见 `fall_core.h` / `csi_stub.h` 头注与仓库 issue）；
3. **交付形式**：C 将调好的参数值填入简单的头文件定义：
   * `#define IMPACT_THRESH  xxxx`
   * `#define STILL_TIME_MS  1500`
   * `#define CSI_FALL_VAR   xxxx`
   A 直接把参数写进主控工程的 `config.h` 中即可生效。

> **实现口径**：判定采用"持续静止计时（1.5s）+ 4s 观察上限"，另提供可选姿态门
> （`POSTURE_CHECK_ENABLE`，默认关闭，待佩戴位置确定后开启）压制"快速坐下"
> 误报。实际宏名以 `firmware/base_station/main/fall_core.h` 为准
> （`IMPACT_THRESH_G` / `STILL_WINDOW_MS` / `PENDING_MAX_MS`），
> 离线自测默认 + 姿态门双构建 19+22 场景全过。C 调参建议：拿 SD 卡 CSV 对真实动作做阈值扫描。

## 三、 B 与 C 之间的规范（测试挑刺与硬件反馈）

C 充当穿戴端的“产品质检员”，两人采用**“现象反馈卡”**进行异步沟通：

* **反馈规范（C 提问题）**：C 戴上设备测试后，若发现问题，按此格式在群里发一条消息：
  > 【测试反馈】
  > * **动作**：连续快走 1 分钟 / 坐在椅子上 / 扑在垫子上；
  > * **异常现象**：电脑收到数据断帧 2 秒 / 走了 10 步没反应 / 穿戴小盒发烫；
  > * **现场状态**：板载 LED 是否在闪烁、电池电量是否充足。
* **硬件移交规范（B 交实物）**：
  * B 每次完成固件烧录或结构加固后，将设备装入小盒子，开关处贴胶带标明“ON/OFF”，直接放在实验室/宿舍固定工位；
  * C 随时取走测试，测完放回，全程无需约时间面对面交接。

## 四、 成员 A 基站内部板间协议（S3 $\leftrightarrow$ FPGA）

固定基站内部，ESP32-S3 与 Artix-7 FPGA 之间经 UART 双向通信：
下行下发声光报警命令，上行报告人机输入（键盘/拨码）状态。
本节为两板间链路的**唯一权威定义**，两侧实现必须逐字段一致。

### 4.1 物理层

| 项 | 值 |
|---|---|
| 介质 | UART 异步串口，3.3V TTL 直连 |
| 波特率 | 115200 |
| 帧格式 | 8N1（8 数据位，无校验位，1 停止位） |
| 方向 | 双向：S3 → FPGA 下行控制帧（§4.3）；FPGA → S3 上行 UI 帧（§4.9） |
| 下行接线 | S3 GPIO17(TX) → FPGA **B15**（右扩展排母上排第 1 脚，同排末位即 GND） |
| 上行接线 | FPGA **C14**（右扩展排母，B15 邻位）→ S3 **GPIO18**（UART1 默认 RX 脚），约束见 `pins.xdc` |
| 共地 | 两板 **GND 必须共地**（与下行同排） |

> UART 空闲态为高电平。FPGA 上电时 rxd 浮空会误码，rxd 需外部上拉或保持 S3 TX 常连接。
>
> 注：FPGA 课程资料中的 UART 引脚 F12/F13 接板上 USB-UART 桥（右侧 UART USB
> 口），F13 未引出至排针；本链路的收发引脚均为扩展排母脚位。

### 4.2 帧格式（8 字节定长，小端）

| 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 0 | 帧头 1 | uint8 | 固定 `0xAA` |
| 1 | 帧头 2 | uint8 | 固定 `0x55` |
| 2 | 命令码 | uint8 | 见 §4.3 / §4.9 |
| 3 | 参数 1 | uint8 | 命令相关 |
| 4~5 | 参数 2 | uint16 | 小端 |
| 6 | 校验和 | uint8 | Byte2~Byte5 共 4 字节的 XOR |
| 7 | 帧尾 | uint8 | 固定 `0x0D` |

示例（ALARM 命令，参数全 0）：`AA 55 01 00 00 00 00 0D`（xor = `01^00^00^00` = `01`）

### 4.3 命令码（下行 S3 → FPGA）

| 命令码 | 名称 | 参数1 | 参数2 | 语义 |
|---|---|---|---|---|
| `0x01` | ALARM | `0x00` | `0x0000` | 跌倒告警：数码管 `FALL` 整屏急闪，蜂鸣器音频载波"三短一停"节拍鸣响，可用 LED（12 颗）与节拍同步爆闪（详见 §4.8） |
| `0x02` | CLEAR | `0x00` | `0x0000` | 告警解除：蜂鸣器立即静音，数码管/LED 恢复按状态码显示 |
| `0x03` | SET_AUDIO | bit0=蜂鸣器静音，bit1=待确认提示音使能 | 载波半周期（`0`=FPGA 默认 2.7kHz） | 运行期蜂鸣器配置：静音优先级高于一切发声（含 POST）；音调运行期可调，无需重综合。bit1=1 时状态 2 期间 FPGA 自发 1Hz 短提示音 |
| `0x10` | SET_STATE | 状态码 | 遥测字 | 同步 S3 判定状态 + 实时合加速度到 FPGA 显示（见下方"参数2 遥测字"） |

**参数2 遥测字（仅 `SET_STATE` 使用）**

| 值 | 含义 |
|---|---|
| `0x0000` ~ `0x0D2B` | 合加速度幅值，单位 **0.01g**（1.00g → `100` = `0x0064`）。合法上限 `2771` |
| `0xFFFF` | **暂无有效遥测**哨兵：FPGA 待确认画面显示 `------` |

- 该字段只影响数码管读数，**不影响 `alarm_on` / `state_code` 语义**，也不改变帧长与校验规则。
- 合法值域上限 `2771` 远小于哨兵 `0xFFFF`，两者不可能混淆（离线自测场景 15 断言）。

状态码（与 S3 `fall_detector` 状态机一致）：

| 值 | 状态 | 含义 |
|---|---|---|
| 0 | IDLE | 静止/无运动 |
| 1 | WALK | 走动 |
| 2 | FALL_PENDING | 冲击已发生，静止确认窗口内 |
| 3 | FALL_CONFIRMED | 跌倒确认 |

### 4.4 接收方（FPGA）容错要求

1. **滑动重同步**：帧头搜索在任意字节流中找 `AA 55`；校验失败或帧尾错误时丢弃当前帧，
   但**继续在后续字节中寻找下一个 `AA 55`**，不得整帧硬对齐丢弃后续数据。
2. **未知命令码**：丢弃该帧（参数不生效），不得进入错误状态。
3. 字节间超时复位为可选实现，仿真验收不强制。

### 4.5 发送方（S3）时序要求

1. 状态类命令只在**状态变化沿**发送，不得按周期重发。
   **例外**：`SET_STATE` 允许作为**遥测刷新帧**按周期重发（0.5/1/2s，OLED 设置页可调，
   默认 1s）。该帧对 FPGA 完全幂等（只做锁存）。
2. ALARM 与 SET_STATE(3) 不同时发：确认跌倒时只发 ALARM。遥测刷新帧在
   `state == CONFIRMED` 期间一律停发；告警冲击幅值由 OLED 告警屏定格显示。
3. 上电初始化完成后发一次 `SET_STATE(0, 0xFFFF)` 作为链路首帧同步
   （FPGA 显示从 `HELLO` 慢闪进入已链路画面）。
4. 帧间最小间隔 ≥ 1ms，由 S3 发送函数保证（发送互斥锁 + 帧间隔保护）。
5. 数据流中断时遥测刷新帧发 `0xFFFF` 哨兵；FPGA 侧另有 **3s 老化**兜底
   （超时待确认画面切成 `------`），不依赖 S3 行为。演示合成读数不受老化约束。
6. **演示模式（FPGA 拨码 SW1=1）对真实状态完全豁免**：OLED 显示与剧本节奏
   不受真实跌倒/告警影响——不抢屏、不暂停、不终止。剧本运行期间真实
   `SET_STATE`/遥测刷新帧停发；**真实 `ALARM`/`CLEAR` 帧永不抑制、直通
   FPGA**，其声光告警在硬件仲裁层穿透承担。**唯一例外**：剧本"解除"步的
   CLEAR 帧在真实告警锁存期间被抑制（防止掐断真实告警蜂鸣；重叠期 FPGA
   画面本就被真实告警覆盖，该抑制对演示不可见）。退出演示（拨回 SW1）后
   OLED 立即回到真实状态——若真实告警仍锁存则直接进入 P0 告警屏。
7. **人工解除告警**：操作者在 OLED 侧按 KEY0 两次（3s 内）确认后，S3 调用
   `fall_detector_force_clear()` 把状态置回 IDLE 并下发既有 `0x02 CLEAR`
   （FPGA 侧不增加命令）。该出口**与**"持续起身活动自动解除"**并存**，
   不改变任何阈值，也不削弱"数据停摆时告警保持"的语义。
   操作层面见 [开关按键使用说明书.md](开关按键使用说明书.md)。

### 4.7 FPGA 上电自检（POST）

FPGA 上电后前 2 秒（`rtl/top.v` 参数 `POST_CYCLES`）强制走告警显示路径：
数码管 `FALL` 急闪、蜂鸣器"三短一停"鸣响、可用 LED（12 颗）随节拍爆闪；
随后进入待机（无链路时 `HELLO` 慢闪）。

- 用途：**单板验证数码管/蜂鸣器/LED 全链路，不需要 S3 在场**。
- 自检期间 UART 命令照常解码锁存，仅显示/蜂鸣输出被覆盖。
- **拨码静音（SW2=1 或 0x03 命令静音位）优先级高于 POST**：静音下自检
  画面照常、蜂鸣器完全无声。
- 不接 S3 时待机画面长期 `HELLO` 慢闪，属预期行为。

### 4.8 声光显示效果定义

数码管整屏显示**完整英文常用词 + 带单位数值**，观众无需图例即可读懂：

```
 无链路    HELLO   0.5Hz 整屏慢闪   "我开机了，在等基站"
 静止(0)   rEAdy   稳定             "链路正常，待机"
 走动(1)   run     稳定             "检测到运动"
 待确认(2) N.NNG   4Hz 整屏快闪     "冲击 N.NN g，确认中"（无遥测 -------
 告警      FALL    3.3Hz 整屏急闪   "跌倒告警"（冲击幅值由 OLED 告警屏定格）
 演示走灯  Ld NN   稳定             "正在点亮第 NN 颗 LED"
 演示自检  全6位同字符步进 / t1..t3 音调档显示
```

- **可用 LED 为 12 颗**（`led[0..11]`）；**LED12~16 按项目要求禁用**，
  `led[15:12]` 恒灭。板上丝印 LED16 无课程引脚映射（无驱动连接）。
- `led[11]` 兼作链路灯：无链路 0.5Hz 慢闪；已链路每收到一帧合法命令闪 60ms。

| 条件 | 数码管（6 位） | 蜂鸣器 | 12 颗 LED |
|---|---|---|---|
| 告警（ALARM / POST / 演示场景4） | `FALL` 整屏约 3.3Hz 急闪 | 约 2.7kHz 载波 × 节拍 响150/停100/响150/停100/响150/静600 ms | 与节拍同步爆闪（响=全亮，停=全灭） |
| 无链路 | `HELLO` 0.5Hz 慢闪 | 静默 | `led[11]` 慢闪；`led[0]` 呼吸灯 |
| `state_code=0` 静止 | `rEAdy` | 静默 | `led[0]` 呼吸灯；`led[11]` 每帧闪 60ms |
| `state_code=1` 走动 | `run` | 静默 | 单灯 + 2 级拖尾环形流水（80ms/步） |
| `state_code=2` 待确认 | `N.NNG` 4Hz 快闪（无遥测 `------`） | 可选 1Hz 短提示音（0x03 bit1） | KITT 式来回扫描（50ms/步） |
| `state_code=3` 已确认 | 同告警 | 同告警 | 同告警 |
| 演示场景 5 走灯 | `Ld NN` | 静默 | 单灯逐颗步进（0.5s/颗） |
| 演示场景 6 自检 | 全 6 位同字符步进 → `t1..t3` | 三档音调试听（KEY9/10 换档） | 呼吸灯 + 链路灯 |

- **音调运行期可调**：0x03 命令 p2 携带载波半周期（0 = 默认 2.7kHz）；
  演示场景 6 提供三档试听（2.7k/3.1k/4.0k），现场选定后经设置页固化。
- **静音三重来源相"或"**：拨码 SW2（本地硬静音）、0x03 命令 bit0、
  设置页 BUZZER 项；静音优先级高于一切发声（含 POST 与告警）。
- **调参位置**：`rtl/buzzer_ctrl.v`、`rtl/seg_display.v`、`rtl/led_ctrl.v`
  （`LED_COUNT` 默认 12）；遥测刷新周期 = OLED 设置页。
- **不变式**：`SEG_INVERT`/`AN_ACTIVE_LOW` 极性、`led[15:12]` 恒灭、
  "告警解除立即静音并复位节拍"语义固定。

### 4.9 FPGA → S3 上行 UI 链路

物理层同 §4.1（同波特率 8N1，FPGA C14 → S3 GPIO18；帧格式与下行对称）。
上行只承载人机输入报告，低带宽：事件即发 + 1s 心跳。

| 命令码 | 名称 | 参数1 | 参数2 | 触发时机 |
|---|---|---|---|---|
| `0x80` | INPUT_SNAP | `0x01` | bit0=演示模式使能（拨码 SW1），bit1=FPGA 本地静音（拨码 SW2） | 上电后首发一次；此后任一位消抖变化即发；另有 1s 周期心跳（3s 无心跳 = UI 链路断） |
| `0x81` | KEY_EVENT | `0x01` | bit[3:0]=键号 0..15（消抖后的按下沿） | 任一矩阵键盘按键按下 |

**键编号即板上丝印 KEY0~KEY15**，且**与矩阵扫描顺序一致**（恒等映射）：
丝印编号等于行主序扫描位置 pos（pos = 行*4+列），扫描起点那一角是
丝印 KEY0、另一端是 KEY15，上行帧键号 = pos（映射集中在
`` `rtl/input_ctrl.v` `` 的 key_number()，为恒等映射）。
若丝印/接线改变，只改 `rtl/input_ctrl.v` 的 `key_number()` 一处置换，
上行帧与本地演示场景选择共用同一编号，改一处两侧同步生效。

**键位功能分配**（S3 侧 OLED 导航）：

| 模式 | 键 | 功能 |
|---|---|---|
| 正常 | KEY13 | 循环翻页 P0→P1→P2→P3→P4→P0 |
| 正常 | KEY14 | 进入设置页（P3） |
| 正常 | KEY15 | 蜂鸣器使能切换 |
| 正常 | KEY0 | 回默认状态页（P0） |
| 设置(P3) | KEY0 / KEY1 | 光标上一项 / 下一项（9 项循环） |
| 设置(P3) | KEY2 / KEY3 | 当前项数值 − / +（即改即存 NVS 即生效） |
| 设置(P3) | KEY14 | 退出设置回状态页 |
| 演示(SW1=1) | KEY0~KEY7 | 场景直选：0=S3 全链路剧本，1=静止，2=走动，3=待确认，4=告警，5=走灯诊断，6=段码+音调自检，7=预留 |
| 演示 | KEY8 | 场景 +1 循环 |
| 演示 | KEY9 / KEY10 | 场景内调参：合成读数 ±0.01g；场景 6 音调互换档 |

**拨码开关分配**（辅助输入，仅"持久电平"型功能）：

| 开关 | 引脚 | 功能 |
|---|---|---|
| SW1 | T8 | 演示模式总开关（0=正常运行 1=演示；退出演示拨回 SW1） |
| SW2 | T7 | 本地硬静音（1=蜂鸣器完全静音，不依赖 S3 在场，含 POST） |

其余拨码留作扩展。**矩阵键盘/拨码的处理在 FPGA 本地完成**（演示场景、
静音、走灯、自检均不依赖 S3 在场）；S3 侧仅负责 OLED 页面导航与设置存储。
